code-atlas                                                     *code-atlas*

code-atlas is a Neovim plugin for call graph and dependency analysis.

Core goals:
  - local function call exploration
  - project-wide caller/callee visibility
  - dependency graph and impact analysis workflows

1. Requirements                                               *code-atlas-requirements*

- Neovim >= 0.10
- Tree-sitter parsers for supported languages
- Optional: telescope.nvim for picker integration

==============================================================================
2. Setup                                                      *code-atlas-setup*

Example using Lua setup:

>
  require("code-atlas").setup({
    depth_limit = 2,
    ui = {
      mode = "tree",
      border = "rounded",
      max_width = 0.8,
      max_height = 0.8,
    },
  })
<

3. Commands                                                   *code-atlas-commands*

- :CodeAtlas
    Open local call graph for function under cursor.

- :CodeAtlasPick
    Open Telescope picker for local functions (requires telescope.nvim).

- :CodeAtlasIndex
    Build project-wide function index.

- :CodeAtlasIndexRefresh
    Refresh project index.

- :CodeAtlasProjectGraph
    Show project call graph (callees) from symbol under cursor.

- :CodeAtlasProjectReverseGraph
    Show reverse project call graph (callers) from symbol under cursor.

- :CodeAtlasLSPGraph
    Show LSP call hierarchy graph (callees) from function under cursor.

- :CodeAtlasLSPReverseGraph
    Show reverse LSP call hierarchy graph (callers) from function under cursor.

- :CodeAtlasLSPDebug
    Show attached LSP client capabilities and last call hierarchy run details.

- :CodeAtlasModuleGraph
    Show module dependency graph rooted at current symbol module.

- :CodeAtlasPackageGraph
    Show package dependency graph rooted at current symbol package.

- :CodeAtlasImportGraph
    Show file import graph rooted at current file.

- :CodeAtlasImportReverseGraph
    Show reverse import graph (dependent files) for current file.

- :CodeAtlasDeadCode
    Show functions with zero incoming callers.

- :CodeAtlasImpact
    Show direct/transitive caller impact for current symbol.

- :CodeAtlasExport [format] [path] [incoming|outgoing] [depth=N] [layout=hierarchical|force]
    Export project graph for current symbol. Format supports json, graphviz
    (dot), and mermaid. Layout supports hierarchical or force metadata.
    Path defaults to the current working directory.

- :CodeAtlasKnowledge [path|path=...] [format=json|jsonl]
                      [include_tests=bool] [include_imports=bool]
                      [include_types=bool] [include_external=bool]
    Build a unified knowledge graph summary. If path is provided, write a
    snapshot with schema_version "knowledge_graph.v1".

- :CodeAtlasArchitecture [include_tests=bool]
                         [unknown_policy=allow|deny]
                         [max_examples=N]
                         [path=...]
                         [format=json]
                         [pretty=bool]
    Show architecture layer/domain grouping, dependency edges, and rule
    violations with example callsites. If path is provided, write a JSON
    snapshot.

- :CodeAtlasUI tree|ascii
    Switch graph UI mode.

==============================================================================
4. Keymaps in graph windows                                   *code-atlas-keymaps*

- <CR>, o   Jump to selected target
- l, <Right>  Expand node
- h, <Left>   Collapse node
- <Tab>       Toggle node expand/collapse
- r           Refresh current view
- q, <Esc>    Close window

==============================================================================
5. Configuration                                              *code-atlas-config*

Default configuration:

>
  {
    depth_limit = 2,
    lsp = {
      enabled = true,
      timeout_ms = 1200,
      prefer_call_hierarchy = false,
      include_external = false,
    },
    resolution = {
      poly_score_window = 25,
      poly_min_confidence = "medium",
      max_poly_targets = 3,
    },
    layout = {
      algorithm = "hierarchical",
      spacing_x = 220,
      spacing_y = 90,
      force_iterations = 24,
    },
    ui = {
      mode = "tree",
      border = "rounded",
      max_width = 0.8,
      max_height = 0.8,
    },
    architecture = {
      include_tests = false,
      unknown_layer_policy = "allow",
      max_violation_examples = 3,
      export_format = "json",
      export_pretty = true,
    },
  }
<

Fields:
  depth_limit   Maximum traversal depth in graph views.
  lsp.enabled   Enable LSP call hierarchy integration.
  lsp.timeout_ms  Timeout for call hierarchy requests.
  lsp.prefer_call_hierarchy  Prefer LSP hierarchy for project graph commands.
  lsp.include_external  Include external library nodes in LSP graph output.
  resolution.poly_score_window  Score gap from best to keep polymorphic targets.
  resolution.poly_min_confidence  Minimum confidence to keep polymorphic targets.
  resolution.max_poly_targets  Maximum targets kept per callsite.
  layout.algorithm  Graph layout metadata algorithm: "hierarchical" or "force".
  layout.spacing_x  Horizontal spacing used by hierarchical layout metadata.
  layout.spacing_y  Vertical spacing used by hierarchical layout metadata.
  layout.force_iterations  Iteration count used by force layout metadata.
  ui.mode       "tree" (interactive) or "ascii" (fallback).
  ui.border     Floating window border style.
  ui.max_width  Max floating width ratio of editor columns.
  ui.max_height Max floating height ratio of editor lines.
  architecture.include_tests  Include test symbols in architecture groups.
  architecture.unknown_layer_policy  Allow/deny dependencies for unknown layers.
  architecture.max_violation_examples  Max violation examples per edge.
  architecture.export_format  Snapshot format for architecture report.
  architecture.export_pretty  Pretty-print architecture snapshot output.

==============================================================================
6. Limitations                                                *code-atlas-limitations*

- Cross-file resolution is currently heuristic name matching.
- Type-aware call resolution is partial (receiver-aware TS/JS method matching).
- Receiver-aware heuristics include TS/JS/Lua and best-effort Python/Go/Rust.
- Project graph includes mixed-source resolution preview with confidence labels.
- Polymorphic callsites are shown as dynamic edges with alternative targets (best-effort).
- LSP call hierarchy availability depends on language server support.
- Very large repositories may require stronger indexing guardrails.
- Architecture layer grouping is heuristic and may need project-specific tuning.
